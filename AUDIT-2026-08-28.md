# Dragon Realms — Comprehensive Audit (2026-08-28)

Read-only audit of the working tree (18 modified, 7 untracked). Method: direct
source review + 6 independent subagent audits (security, correctness,
quality/ops), with every critical/high claim re-verified in source or
reproduced by a live probe. Untracked file — delete freely.

## Verified baseline

- `npm test`: 359/359 pass (17-35s). Syntax: 166 files clean.
- Coverage: 93.85% lines / 73.5% branches. Weak spots: `server/gm.js` 64%,
  `server/boost.js` 57%, `server/session.js` 75%, `server/commands/world.js` 70%.
- `npm run verify`: green in isolation; see O1 for the shared-world caveat.

## P0 — fix before anything else

- **D0. Admin launcher enables the debug API with a literal token.**
  `admin/main.swift:139-140` always sets `DR_ENABLE_DEBUG_API=1` and defaults
  `DR_DEBUG_TOKEN` to the string `mapper-debug-1`. The debug API accepts
  state-mutating fixtures (teleport, setSkills, hp/mana/silver, clearCombat,
  die — `server/api.js` debug route). Combined with the all-interface bind
  (S2), anyone network-adjacent to a world started by the menu-bar app can
  rewrite game state with a credential that is committed to the repo.
  Fix: never enable the debug API from the launcher without explicit opt-in +
  a mandatory high-entropy token; remove the literal fallback.

## Critical

- **C1. Room spawns are never depleted by kills.** `CombatManager.start`
  clones enemies from definitions (`server/combat-manager.js:26-35`);
  `Combat.killCreature` only marks the clone dead (`server/combat.js:310-316`).
  Nothing ever sets a `roomCreatures` instance `alive=false` outside
  `makeCreature`/`respawnTick`, so the whole respawn/throttle lifecycle is dead
  code. Probe (x3 independent): after `killCreature`,
  `{instanceAlive:true, combatDead:true}`. One room can be farmed forever;
  multiple players can kill the same logical spawn; aggressive mobs re-engage
  after death. Fix: carry the instance uid into Combat, mark dead + respawnAt
  on kill, refuse a second combat claiming the same instance.

## High

- **C2. Duels tick twice per second.** `startDuel`/`startAssault` store one
  Combat under both charIds (`combat-manager.js:88-89`); `startTicker`
  iterates `[...this.combats.values()]` without dedupe (`:219-225`). Probe:
  `{mapSize:2, unique:1, same:true}`. All duel pacing runs ~2x with duplicate
  output. Fix: dedupe by object identity (`new Set(...)`) or index by combat id.
- **C3. GM world reload ignores live combat and spawn state.**
  `server/gm.js:476-489` replaces every room's creature array unconditionally
  (entries missing uid/respawnAt) while combats keep stale clones — dead mobs
  instantly reappear, throttle bypassed. Fix: reconcile, don't replace.
- **C9. Lethal PvP spells never resolve the duel.** Every weapon path checks
  `target.def.controller` and routes to `defenderDefeated()` with HP sync
  (`server/combat.js:271,291-294,595,646,1142,1347-1351`) — the cast path does
  not: `cast()` ends `if (target.hp <= 0) this.killCreature(target)`
  (`combat.js:810`) and `killCreature` has no controller branch. A lethal
  offensive spell against a player-controlled defender pushes a corpse of the
  player, can stamp an empathic stain, ends the fight as a creature kill —
  while the real defender stays alive at full HP in the room.
- **S1. Stored XSS in the GM console via player aliases.** `aliases.command`
  is arbitrary persisted player text (`server/player.js:675-684`); the GM DB
  browser interpolates `JSON.stringify(row[c])` into innerHTML unescaped
  (`public/js/gm-console.js:196-204`). Any player can plant a payload that
  executes in the GM origin, where the GM token sits in localStorage. The
  same file has many more unescaped interpolations (names, room data, table
  names, error messages — gm-console.js:37-115,182,193). Fix: render cells
  with textContent/createElement throughout.
- **S2. Production-insecure defaults.** API enabled unless
  `DR_ENABLE_API=0` (`server/index.js:31`) contradicts README/docs/api.md
  ("opt-in"); `server.listen(PORT)` binds all interfaces while logging a
  localhost URL (`index.js:67`); default GM token is `Math.random()` ~50 bits
  (`index.js:17-30`) and is adopted from the predictable file
  `/tmp/dr-world-token.json` if pre-created by a local attacker. Fix: opt-in
  API, bind 127.0.0.1 by default, `crypto.randomBytes(32).toString('hex')`
  token, startup log stating exposure.
- **D1. Shop purchases never decrement stock.** `economy.js:51-52` builds
  entries with a copied primitive `q`; `target.q -= qty` (`:64`) mutates the
  copy, not `shop.stock[id]`. Every shop sells infinitely; configured stock
  limits in `data/npcs.js` are ineffective. Fix: decrement
  `target.shop.stock[target.item.id]`.
- **O1. `npm run verify` is not a reliable gate on a shared world.** Corpus
  replay failed twice under audit with `CORPUS DRIFT` caused by unrelated
  online players appearing in room rosters (`scripts/client-corpus.mjs:67-76`
  doesn't normalize rosters/ordering); `scripts/verify.mjs:43-51` also treats
  any successful `GET /` as a compatible server, and silently skips the corpus
  when none is reachable while still printing "All checks passed". Fix: boot
  an isolated temp-DB server inside verify (or normalize volatile fields), and
  never claim all-passed with a skipped check.

## Medium

- **C4. Roundtime bypass via unlisted aliases.** `RT_BLOCK`
  (`server/commands/index.js:40-48`) omits `kill` (alias of `attack`,
  `combat.js:590`) and `bash`/`shield-bash`/`disarm`/`trip` (`:596-599`).
  Real WS/API sessions can fire these mid-roundtime. Fix: resolve aliases
  before the RT gate or add all aliases.
- **C5. Corrupt `inventory.bundle` bricks character load.**
  `server/player.js:296-301` parses unguarded while every sibling field is
  defensive. One bad row = that character cannot log in. Fix: safe parse with
  fallback (mirror the persistent_state pattern).
- **C6. Stale session can mutate scripts after losing the character.**
  `scripts_put`/`scripts_del`/`gen_starter` (`server/session.js:191-210`) lack
  the ownership predicate the input path uses (`session.js:84,179`). A
  superseded socket can overwrite the current owner's scripts.
- **C7. Metadata loss on equip/death.** `equipItem` INSERT omits `maker`
  (`server/player.js:824-825`); corpse serialization keeps only id/qty
  (`server/corpses.js:29-39`).
- **C10. Invalid prepared cast: mana free, prep and roundtime spent.**
  `p.prepared = null` (`magic.js:119`) and `setRoundtime` (`:122`) run before
  the no-target return (`:172`); no mana is debited on that path. Probe:
  mana 100→100, prepared→null, RT active.
- **D2. Innocent pleas can reset jail indefinitely.** Only guard is
  `remaining > 60` (`server/commands/world.js:171-177`); below 60s each plea
  re-extends the sentence — a low-heat player can loop forever.
- **D3. Auth lockout reset race.** Successful login's SELECT-then-reset
  (`server/auth.js:163-200`) is not atomic; a concurrent failing login can
  lock the account between the two, and the success erases the lock. Narrow
  window; the per-attempt UPDATE itself is atomic.
- **S3. `public/live/` served unauthenticated.** Static handler serves
  `sweeps.db` (~832KB sim history with names/commands) and all sim logs. Fine
  on loopback; a leak if exposed. Fix: deny `.db*`/`.log` at minimum.
- **S5/S6. No pre-auth IP throttling.** Registration unlimited; per-account
  lockout is the only brake; the 2-active/32-queued scrypt pool can be
  saturated (`server/api.js:199-210`, `server/auth.js:17-53`); any known
  username can be locked out for 10 minutes with 5 wrong passwords
  (`auth.js:144-188`).
- **S7. Gags panel HTML injection.** `${g.pattern}` unescaped into innerHTML
  (`public/js/gags.js:46-48`). Mostly self-XSS, but patterns arrive via
  importConfig JSON too. Same fix family as S1.
- **O2. Abrupt shutdown loses up to 60s of progress.** SIGINT/SIGTERM:
  `game.stop(); closeDb(); exit(0)` (`server/index.js:78-83`);
  `game.stop()` does not persist active players (autosave is 60s) and the
  HTTP/WSS handles are never closed (`index.js:65` discards the WSS).
  Fix: bounded graceful drain — stop accepting, close sockets, persist all,
  close DB, exit.

## Low

- **C8.** Names case-sensitive in DB (`UNIQUE`), case-insensitive in gameplay
  lookup (`server/db.js:39-44`, `server/player.js:149-173`) — Alice/alice
  ambiguity. Fix: normalized uniqueness index.
- **C11.** Snipe consumes ammunition before the stamina gate
  (`server/combat.js:615-616`).
- **C12.** Shield bash spends stamina before checking a shield is equipped
  (`server/combat.js:1083-1089`). (C11/C12 same class: validate before consume.)
- **D4.** Character-slot limit is check-then-insert without a transaction
  (`server/player.js:149-172`) — concurrent creates can exceed MAX_CHARS.
- **S4.** Static containment is prefix-only (`filePath.startsWith(publicDir)`,
  `server/static.js:20-29`): not separator-bounded (public vs publicity) and
  follows symlinks. Not exploitable as deployed; handler is reusable.
  Fix: realpath + `root + path.sep` boundary + sibling-prefix regression test.
- **O3.** Justice test flake observed once (pass on rerun):
  `test/world.test.mjs:389-400` asserts confiscation after up to 20
  probabilistic arrest attempts. Fix: inject/stub the arrest RNG.
- **O4.** Port preflight race; no `server.on('error')` for EADDRINUSE
  (`server/index.js:38-67`). Let `listen()` be the authority.
- **O5.** `scripts/live-sim.mjs:23` uses `?bot=1` while its docs claim
  indistinguishability from ordinary players.
- **O6.** `verify-docs` regenerates files before comparing (state-changing
  verify). Add a pure check mode.
- **O7.** Client reconnect is a flat 2s loop with no backoff/jitter/teardown
  (`public/js/net.js:21-26`, `spectate.js:60`); permanent 500ms script and
  gamepad intervals.
- **O8.** `scripts/client-regression.mjs` ignores several `waitFor()` results
  before unconditional passing checks, and uses a fixed CDP port (9360) that
  can attach to a stale browser.
- **O10.** No CI workflow exists (no `.github/`); nothing runs
  test/verify-docs automatically.
- **O11.** Observability is console-only (no levels/rotation/correlation);
  SQLite WAL checkpoint/backup procedure undocumented and untested.
- **O12.** Docs contradictions: "zero runtime dependencies" vs `ws@8.21.3`
  (package.json, AGENTS.md); API default-on vs documented opt-in.
  Admin build script comment references `bins/dradmin` but emits
  `bin/admin/dragonrealms-admin`.

## Concerns (not confirmed exploitable)

- Hand-written GM SQL validator (`server/gm.js:197-353`) is solid
  defense-in-depth but prefer a read-only connection/authorizer long-term.
- `WAITFORRE`/`MATCHRE` compile user regexes unbounded
  (`public/js/script-engine.js:84-97`) — self-DoS; shared/GM scripts could
  freeze an operator's client.
- GM bearer tokens have no origin binding, which amplifies S1.
- `server/gm.js:77-80` uses `exec("open ...")` on a server-derived path —
  prefer `execFile('open', [path])`.
- Unauthenticated `/api/health` returns the online roster with names/guilds/
  circles/bot flags (`server/api.js:192-197`) — aggregation or auth.

## Strengths

scrypt + dummy-work unknown-user path + timing-safe compares; account-scoped
character access; GM DB allowlist with sensitive-table/column blocks and row
caps; WS payload/rate limits with socket error handlers (survived a real
oversized-frame test); runtime-ownership guards on persistence; 359 broad

## Addendum — final batch (6th audit fan-out)

Three claims re-verified in source before adding:

- **S1 strengthened — second, larger XSS vector.** Besides aliases, `putScript`
  persists up to 8000 chars of arbitrary player text into
  `characters.persistent_state` (`server/player.js:707-714`), and `characters`
  is GM-browsable (only `accounts`/`sessions` are blocked, gm.js:200-218).
  Script bodies render unescaped through the same `renderDbRows` path. Same
  fix covers both: escape/textContent the DB renderer.
- **C13 (MEDIUM). `spellsKnown` is persisted but ignored on load.**
  `persistentStateFor` stores it (`player.js:99`), but `loadPlayer` rebuilds
  known-spells from the full circle curriculum and reads back only
  `spellsForgotten` (`player.js:237-240`). Probe: forget a spell, save, reload
  → forgotten list survives but `spellsKnown` contains it again. The
  curriculum-derivation comment suggests partial intent; either stop
  persisting spellsKnown or honor it (minus forgotten) on load. Needs a
  save/reload consistency test.
- **O1 strengthened — the corpus leg is close to tautological.**
  `scripts/verify.mjs:47-49` captures a fresh corpus then immediately replays
  it against the same build: it proves only that the build reproduces its own
  output, not that behavior is preserved across changes. Fix both halves:
  replay a version-controlled approved baseline, and isolate the server.

New findings from this batch (subagent-verified, spot-checked):

- **D5 (MEDIUM).** Vault metadata misalignment: `auctionPrune` merges an
  expired lot's qty into an existing vault row without appending
  `lot.instances` (`server/economy.js:166-170`); `vaultRetrieve` then defaults
  missing metadata entries (`instanceMetadata({})`) — durability/quality/maker
  silently lost on retrieval.
- **D6 (MEDIUM).** `auctionOffer` removes the item from inventory before the
  INSERT, with no transaction or compensation (`server/pvp.js:187-200`) — a
  failed/overflowing insert permanently destroys the escrowed item.
- **C14 (LOW).** Paladin loses 5 soul for challenging a target before target
  validation (`server/pvp.js:14-23`) — a mistyped `duel` costs permanent soul.
- **C15 (LOW, cross-confirmed by two batches).** `createCharacter` calls
  `baseStatsFor(race)` before validating race exists (`player.js:149-156`) —
  invalid input yields a TypeError instead of the intended validation error.
- **S2 strengthened.** The token file write to
  `/tmp/dr-world-token-<port>.json` is not exclusive and follows pre-existing
  symlinks (`server/index.js:28,72-74`) — a local attacker can pre-plant a
  symlink and capture the GM token. Reinforces randomBytes + non-world-
  writable location.
- **O13 (MEDIUM, client).** GM console leaks a spectator WebSocket per player
  selection (never closed on switching, gm-console.js:117-128) and re-binds
  the DB query Enter listener on every refresh (gm-console.js:176-191) —
  duplicate queries per keypress.
- **O14 (MEDIUM, client).** A malformed user script regex throws during
  `runner.start()` (`scripts.js:30-34`; `script-engine.js:86,96`) without
  clearing the active registry — the client rejects all further scripts with
  "already running" until page reload. Validate regexes at parse time; wrap
  start/feed and fail closed.
- **Concern added.** GM DB browser accepts FROM-less SELECTs, so
  `SELECT randomblob(1000000000) LIMIT 1` passes validation and can spike
  memory (gm.js:203-286) — GM-credential-gated DoS; bound expression cost or
  use a read-only connection with an authorizer.

Test gaps added: spell forget→save→reload consistency; vault+expired-auction
metadata merge/retrieve; auction escrow failure injection; hostile character
name through GM roster/player-inspector rendering.

## Addendum 2 — batch 7 (cross-check wave; mostly re-confirmation)

New findings (Bard splash verified by direct source read during C9 review;
rest subagent-verified with probes):

- **C16 (HIGH). Bard splash leaves enemies dead-but-not-dead.** The enchante
  splash loop subtracts HP from every other enemy in the fight
  (combat.js:765-772), but only the primary target is passed to killCreature
  (combat.js:810). A secondary enemy driven to ≤0 HP stays in aliveEnemies:
  no corpse, no loot, no quest credit, fight can stall unwinnable.
- **C17 (MEDIUM). Same-socket concurrent auth race.** route() dispatches
  login/register without serialization or a generation guard
  (session.js:258-269); two rapid logins race, last-to-resolve overwrites
  token/account state, client sees interleaved authed frames.
- **D7 (MEDIUM). Chargen allocations lost on pre-entry disconnect.** Stat
  allocation lives only in the draft Player until world entry
  (chargen.js:55-96); closing the socket after allocating silently reverts it.
- **D8 (MEDIUM). savePlayer is not transactional.** Character/skills/
  equipment/inventory/quest writes are separate statements (player.js:380-425)
  — a crash mid-save persists mixed state.
- **S8 (MEDIUM). GM characters-delete contradicts the read-only contract.**
  Destructive, no confirmation nonce, no audit record, no batch cap
  (gm.js:364-388).
- **O15. Concurrent sweep artifacts are non-atomic.** scripts/index.json and
  fidelity-summary.jsonl use read-filter-rewrite / raw appends
  (race-guild-sweep.mjs:1649-1706) — concurrent runs can lose entries.
- **O16. build-roadmap regex-parses guilds.js source text**
  (build-roadmap.mjs:14-25) instead of importing data — formatting changes
  silently misparse requirements.
- **O17. db.js migrations catch all ALTER TABLE errors as duplicate-column**
  (db.js:130-181) — permission/corruption failures are swallowed at startup.
- **C3 strengthened:** GM reload also ignores SPAWN_MULT.
- Maintainability: gm-console collapses all endpoint errors into one generic
  token message (gm-console.js:18-29,215-225).

Test gaps added: bard multi-enemy splash kills (corpse/credit/termination);
same-socket concurrent logins; disconnect-before-enter chargen; savePlayer
fault injection; SIGTERM shutdown integration; GM delete authorization/audit.

## Addendum 3 — batch 8 (final wave)

- **C17 upgraded to HIGH.** The auth race is worse than interleaving:
  login → immediate `logout` (or a second login) lets the stale completion
  call `startAccountSession()` afterwards, resurrecting the session after
  logout or switching accounts (session.js:240,258-278). Needs a request
  generation/state check after each await.
- **C18 (MEDIUM).** `vaultStore` drops `entry.bundle` (economy.js:142) and
  `vaultRetrieve` recreates an unbundled stack (economy.js:164) — retrieving
  bundled pelts/ore can suddenly encumber the player; bundle state is not
  durable across vault round-trips.
- **O3 strengthened — second observed flake.** This batch's test run actually
  failed `test/ranges.test.mjs:29-43` (test 233, "attack presses in to
  melee…", 358/359) — a tight `combat.tick()` loop with an arbitrary 60-iter
  bound. Two distinct flaky tests now observed live (justice + ranges).
- **S8 strengthened.** Mutating GM endpoints (`characters-delete`,
  `admin/reload`) are not method-gated — `gmRequest` never enforces POST/405 —
  and there is no audit record beyond console output (gm.js:59-64,367-387).
- **O18 (MEDIUM).** `Game.init()` is not idempotent (game.js:69-100): a
  second call leaks the first set of tickers and doubles mana/weather/
  autosave/pulse/respawn processing. Add an initialized guard.
- **O19 (LOW, client bundle).** `router.js:153-156` persists the auth token
  without try/catch (throws under storage-disabled/quota); `net.js` reconnect
  lacks a generation token so a stale socket's close can open a duplicate
  session; `scripts.js:53-56` feeds the runner every 500ms even when
  disconnected/hidden; `panels.js:78-88` 200ms capture window can misroute
  slow multi-line panel responses. GM-token-in-localStorage threat model
  (CLIENT-004) reinforces the short-lived scoped GM session direction.
- **Discrepancy resolved:** this batch claimed shop stock is shared mutable
  state depleted for all players (DR-AUDIT-002); direct source read shows
  `entries` copies `q` as a primitive (economy.js:51-52), so D1 stands —
  stock is never decremented at all, not shared-depleted.
- Task 1 of this batch hit its iteration cap with empty output; security
  coverage is complete from the seven other audits (all cross-confirmed).

**Audit closed — 8 of 8 batches integrated, none outstanding.**

## Addendum 6 — batch 11 (synthesis; final batch)

- **O20 extended — the ladder has two independent defects.** Even with the
  missing else-jump fixed, consecutive legs are invalid: `candidateRooms()`
  stores hub-relative paths ("Paths are rooted at arena.id") and
  buildHuntScript emits each leg's `moves(c.fromHere)` directly after the
  previous candidate without returning to the hub (script-gen.mjs:269-279,
