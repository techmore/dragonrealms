🧭 SEP — Small, Evaluated Profiles

A practical roadmap for local AI script writers, map builders, and deterministic Kaizen tooling. The model proposes; the repository, harness, and tests decide.

North star

Build small, repeatable Pi profiles around a local Qwen model that produce DragonRealms changes in the project’s conventions, while keeping current game truth in files and correctness in executable checks.

Success definition: fewer invalid scripts, unavailable-item requests, broken routes, and review cycles on a held-out task set—without allowing an LLM into the runtime Kaizen loop.

Roadmap stages

NOW

1. Deterministic harness

Validate generated scripts, commands, shop inventory, room routes, circle requirements, syntax, and focused tests automatically.

NEXT

2. Pi profiles + skills

Create separate profiles for script engineering, map building, and evidence review. Give each a closed skill set and explicit output schema.

NEXT

3. Training corpus

Collect successful patches, failed hypotheses, log diagnoses, valid scripts, map facts, and test-backed corrections. Hold out evaluation examples.

LATER

4. LoRA experiment

Fine-tune the Qwen base with a small adapter only after the harness and corpus are stable. Compare against the untuned model.

LATER

5. Promotion gates

Promote an adapter only when it beats the base model on held-out correctness, test pass rate, and invalid-output rate.

GUARDRAIL

6. No-LLM Kaizen loop

Runs, metrics, log summaries, regression detection, and variant promotion remain ordinary code with reproducible receipts.

First implementation backlog

  1. Define task schemas. Script request, map request, diagnosis, patch, evidence, and test-result JSON.
  2. Build the validator. Reject unknown commands, unavailable shop items, invalid room IDs, malformed DR scripts, and edits without focused tests.
  3. Extract the corpus. Start with the Kaizen logs: gate owner, hypothesis, change, outcome, and regression reason.
  4. Write Pi resources. Project-local skills for script-writer and mapper; profiles specify model, skills, tools, and output format.
  5. Benchmark the base model. Freeze 20–30 held-out tasks before any fine-tuning so improvement is measurable.
  6. Train one adapter. Use LoRA/SFT for conventions and recurring output patterns, not for mutable world facts.

Model strategy

Fine-tune

Useful for DragonRealms syntax, repository conventions, structured outputs, and recurring diagnosis patterns.

Retrieve

Use current data files, shop inventories, world graph, requirements, and recent logs for facts that change.

Verify

Use Node checks, unit tests, route replay, script execution, and sim evidence as the final authority.

Decision gates

Gate A: Validator catches known failures before model quality is measured.
Gate B: Base Pi profile completes representative tasks with evidence and tests.
Gate C: Adapter improves held-out pass rate without increasing unsafe or stale-fact outputs.
Gate D: Promotion is reversible and the deterministic harness remains the authority.
