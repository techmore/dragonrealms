SPEEDRUNS — RUN & EDIT GUIDE

How to launch agent sweeps, read the results, and edit the kaizen stack. Zero dependencies, no build step.
← Sims board Admin dash Sim architecture Barbarian roadmap

1 · Quick start

The world server must be running first (single-instance guarded — a second instance refuses rather than double-binding):

npm start                # world on :3000 (curl http://localhost:3000/ → 200)

Then launch a sweep. This is the standard 15-minute kaizen pass:

node scripts/race-guild-sweep.mjs --guilds barbarian --races human,gortog,halfling --minutes 15 --boost 20

Watch it live: open /sims.html → 03 · Evidence — the live cards sit above the runs table (guild icon + race + script in the title, EXP bar, watch link, expandable metrics). Every agent also streams to ?spectate=<char>.

2 · Sweep CLI

FlagMeaning
--guilds a,b,cGuilds to run. Only guilds with a GUILD_SCRIPTS entry in data/guild-scripts.js are targetable. Comma list, or omit with --all.
--races a,b,cRaces to cross with each guild. Must exist in data/races.js. Omit with --all to use the curated per-guild RACE_MATRIX (fit / mid / poor stat fits).
--minutes NPer-agent wall-clock cap. 15 is the standard kaizen window; verdicts compare against per-guild baselines (~50/h barbarian, ~45/h warmage, ~42/h paladin, ~45/h thief, ~33/h necromancer).
--boost NTest-only exp multiplier (1–100). Shows as [BOOST xN] in the prompt. Use 20 for kaizen passes.
--allThe curated race × guild matrix (concurrent-safe: each run gets a random run-id suffix so characters never collide).
--benchmarkMulti-leg experiment mode (legs compared against historical best; writes experiment-index.json).
--reportRender the sweeps history (public/live/sweeps.db) as a guild × race fidelity table.

3 · Run lifecycle & artifacts

Each agent: HTTP login → chargen (race/guild stat spread) → bazaar arm (club, knives, armor ladder) → walk to the nearest legal arena → SCAN → FIGHT → REST loop → periodic guild-hall trips (every ~4 kills or 4 minutes; readiness-gated) → verdict at the time cap.

ArtifactWhat it is
public/live/fidelity-<guild>-<race>.logPer-agent stream: milestones, every script> command, [progress] ticks, [gaps]/[reqs] gate samples, verdict. Append-only — the last === sweep run <id> segment is the live one.
public/live/fidelity-summary.jsonlOne JSON row per finished agent (what the sims.html runs table reads).
public/live/sweeps.dbSQLite history — every run appends a row (--report reads it). Sim artifact, not game state.
public/live/index.jsonLive-log discovery list (what the live panel polls).

Verdict vocabulary: healthy (≥ baseline kill rate, moving) · slow (below baseline) · wedged (no kills/circles/trains/moves progress — the log names the room). Timestamps in logs are UTC; file mtimes are local.

5 · Script DSL cheat sheet

Verbs
  put <command>        # send to the game (parks on roundtime, retries at the deadline)
  move <dir>           # walk (bare dirs n/s/e/w/ne/nw/se/sw/up/down/out are sent as-is)
  wait | pause <secs>  # wait for a prompt / wait N seconds
  waitfor <text> | waitforre </re/&i>
  matchre <label> <re> | matchwait [secs]   # register matcher, wait for any hit or timeout
  iflt/ifge/ifgt <var> <n> [goto] <label>   # numeric branch on live state
  ife/ifne <var> <value> [goto] <label>     # string branch (%room has a roomNow fallback)
  setvariable <name> [value] | goto <label> | echo <text> | exit
  putrun <script>      # nest another library script (mega = putrun hunt + putrun circle)

Live %vars
  %hp %maxhp %mana %maxmana %circle %rt %silver %tdp %combat %rage %bleed
  %room %pcount %wsp (wielded weapon skill) %target (fight-loop substitution)
  %wsr_<skill> (rank of any WEAPON-pool skill)

6 · The kaizen loop

Observe — read the verdicts, the final [reqs]/[gaps] per agent, and the kaizen counters (forages, circle attempts, circle-ups). Choose — one defect or one starved exp pool, highest leverage. Act — the smallest script-gen / engine / harness change targeting it. Verify — re-run the sweep and compare kills/hour and gate shortfall against the previous run. Keep only changes that improved the numbers.

Known lessons baked into the code (regressions here are the usual suspects):

  • Stale counters: never emit a state token conditionally — an absent [PLAYERS:n] left a nonzero crowd frozen in %pcount and agents patrolled empty rooms for 14 minutes.
  • Hall trips need a walk leg: any regenerated script must carry a real route from where the agent stands (pureDiskPath), or it strands mid-map.
  • Gate-ready ≠ circling: the CIRCLE_READY hall trip reads the hallPath parameter — a cap.hallPath typo once made every "ready" agent keep farming (fleet-wide 0 circle-ups).
  • Over-gain: combat pours ranks into evasion/parry/1st-weapon regardless; idle time (respawn waits) is the place to train starved pools — hence put forage in WANDER.
  • Guild-skill pools (conviction, empathy, thanatology, summoning) train at the hall, not in the field — they are the last blockers to circle-2, not navigation.

7 · Before you commit

node --check <every .js/.mjs you touched>
npm test                # domain + api + static suites (sims.html logic: test/scripts.test.mjs)
node --test test/scripts.test.mjs test/script-ownership.test.mjs   # engine + generator units

Parallel sessions edit this repo. Check git status and file mtimes before restructuring shared files (guild-scripts.js, script-gen.mjs), stage only your files, and never git add -A during a fidelity pass.
